# Specification: vsphere-provider-upgrade

> Generated by Forge | Survey: 4 agents + 3 researchers | Interview: 36 answers (+5 auto-discovered facts)
> Date: 2026-09-24

## Problem Statement

The AlphaBravo vSphere Crossplane provider must move from Terraform provider `hashicorp/vsphere` 2.12.0 on upjet 0.9 to `vmware/vsphere` 2.15.1 on upjet v2, as a MIGRATION of all existing resources rather than a rewrite. [derived from A-003, A-011]
The migrated provider must run the vSphere provider in-process (no-fork), serve both cluster-scoped and namespaced managed resources under a new `vsphere.alphabravo.io` API root, and never depend on BSL-licensed Terraform. [derived from A-004, A-005, A-007, A-008]
It is done only when it builds cleanly, passes a lab end-to-end test on k3s with Crossplane v2, and v2.15.1 is published to Docker Hub as a multi-arch package. [from A-021]

- Migrate every resource in the Source Inventory to upjet v2 with both cluster-scoped and namespaced variants. [derived from A-003, A-011]

- In-process vCenter client cache per ProviderConfig plus credentials hash. [from A-015]
- Credentials Secret keeps its keys and accepts string or native JSON values. [from A-016]
- Tagging that mirrors the Terraform provider version, with a `-N` suffix for provider-only fixes. [derived from A-017, A-020]
- Publishing through make targets plus a RELEASING.md runbook, with interactive Docker Hub login. [from A-018]
- A minimal PR CI workflow replacing the Upbound workflows. [from A-019]
- A scripted, manually-run lab e2e on k3s against Crossplane v2.2.0 and v2.4.2. [derived from A-021, A-022, A-023]
- Targeted, non-blocking unit tests for credential parsing and the session cache. [from A-024]
- Foundation cleanup: docs and package metadata, dead files, runtime image base, golangci v2 config. [from A-025]
- MIGRATION.md documenting the old-to-new mapping for the Pioneer follow-up. [from A-026]
- Crossplane SafeStart capability wired per the template, non-blocking. [from A-030]
- Delivery as one PR with logical commits. [from A-028]

### Out of Scope
- Changes to the Pioneer codebase itself; only MIGRATION.md is provided. [derived from A-026]
- Publishing from CI or storing Docker Hub credentials in CI. [derived from A-018, A-019]
- Deleting or rewriting existing Docker Hub tags. [derived from A-029]
- Terraform provider versions newer than 2.15.1, since later releases drop vSphere 7. [derived from A-011 + reality.md Research Findings]
- A hand-written Go schema generator or OpenTofu build path; both stay unused fallbacks. [derived from A-007]
- Promoting any resource to v1beta1. [derived from A-010]

### Architecture

**Component diagram:**
- `cmd/generator/main.go` builds `config.GetProvider()` and `config.GetProviderNamespaced()`, both with `WithTerraformProvider(vsphere.Provider())` and `WithTerraformPluginSDKIncludeList(ExternalNameConfigured())`, then calls `pipeline.Run(pc, pns, root)`. [derived from A-004, A-027 + survey/research-upjet-v2-migration.md]
- Shared configurators in `config/vsphere_*` are applied to both providers by one registration list. [from A-027]
- `cmd/provider/main.go` registers both scheme sets and sets up `internal/controller/cluster` and `internal/controller/namespaced` (gated with SafeStart when RBAC allows), sharing one TerraformSetupBuilder and one session cache. [derived from A-015, A-030 + survey/research-upjet-v2-migration.md]

**Dependency flow:**
- Generated controllers call `tjcontroller.NewTerraformPluginSDKAsyncConnector` with `SetupFn = clients.TerraformSetupBuilder`, which resolves the legacy or modern ProviderConfig, extracts and types the credentials, then returns the cached or new configured Meta. [derived from A-004, A-015, A-016 + survey/research-upjet-v2-migration.md]

## Destination Naming Rule

Each Terraform resource `vsphere_X` keeps its current short group and is generated twice: `SHORTGROUP.vsphere.alphabravo.io` (cluster-scoped) and `SHORTGROUP.vsphere.m.alphabravo.io` (namespaced), both at version v1alpha1. Kind = legacy Kind with only the leading `VSphere` prefix stripped, remaining casing unchanged. New resources: `vsphere_distributed_virtual_switch_pvlan_mapping` becomes networking/DistributedVirtualSwitchPvlanMapping; `vsphere_configuration_profile` becomes hostandclustermanagement/ConfigurationProfile. Provider config types live in `vsphere.alphabravo.io` (cluster) and `vsphere.m.alphabravo.io` (namespaced). Config source: one shared configurator package per resource family under `config/`, applied to both providers. [derived from A-008, A-009, A-010, A-011, A-027]
